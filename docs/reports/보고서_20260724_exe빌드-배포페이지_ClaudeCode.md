# 완료보고서 — 단일 exe 배포 + 다운로드 페이지 연결 (v0.5.0)

- 작성일: 2026-07-24
- 작성자: Claude Code
- 프로젝트: smart-alt-tab
- 버전: v0.4.3 → **v0.5.0**

## 1. 배경

직전 세션 핸드오프의 남은 백로그 두 건 중 "exe 빌드 + GitHub Pages 다운로드 버튼 연결"을
진행했다. 나머지 한 건인 PRD M4(창 썸네일 미리보기)는 **제외 확정**했다.

배포 페이지는 그동안 "다운로드 준비 중"으로 비활성 상태였고, 설치 방법이 `git clone` +
`py -3.13 run.py`뿐이었다. 이 앱의 대상 사용자가 저시력 사용자라는 점을 생각하면, Python을
설치하고 명령줄을 다루게 하는 것은 사실상 배포가 아니다.

## 2. M4(썸네일 미리보기) 제외 결정

**넣지 않기로 확정했다. 저시력 사용자에게는 없는 편이 낫다.**

- 목록에 들어갈 크기의 썸네일은 저시력 사용자가 어차피 식별하지 못한다. 판별에 기여하지 않는
  요소가 화면을 차지하는 셈이다.
- 그 자리는 이 앱의 유일한 존재 이유인 **큰 글씨 창 제목**이 써야 한다. 썸네일을 넣으면 제목
  글자 크기나 한 화면에 보이는 창 개수 중 하나를 반드시 희생하게 된다.
- 축소된 창 미리보기는 대비가 제각각이라 고대비 다크 원칙과도 충돌한다.

되살릴 조건: 썸네일을 제목 크기를 줄이지 않고 배치할 수 있고, 저시력 사용자에게 실제로
판별에 도움이 된다는 근거가 생겼을 때만. 사유는 `docs/prd/`의 마일스톤 절에 기록했다.

## 3. 작업 내용

### 3.1 exe 빌드 스크립트 신규 작성 — `scripts/build_exe.ps1`

PyInstaller onefile로 `dist\smart-alt-tab.exe`(10MB)를 만든다.

- `--onefile --windowed`: 파일 하나, 콘솔창 없음. 대상 사용자가 "받아서 두 번 누르면 되는"
  형태여야 한다.
- `--paths src`: `run.py`가 `sys.path`를 **런타임에** 조작하므로, PyInstaller의 정적 분석에는
  경로를 따로 알려줘야 `smart_alt_tab` 패키지를 찾는다. 없으면 빌드는 되지만 실행 시 죽는다.
- `--uac-admin`은 **일부러 넣지 않았다**. 넣으면 수동 실행마다 UAC 창이 뜬다. 관리자 권한이
  필요한 경우(관리자로 뜬 Cursor 등)는 작업 스케줄러 등록으로 해결하며, 그쪽은 UAC가 안 뜬다.
- PyInstaller `--clean`을 쓰지 않는다: 중간 파일(`build\...\localpycs`) 삭제 중 간헐적으로
  `PermissionError: [WinError 5]`로 빌드 전체가 죽었다(실측). 스크립트가 직접 `build` 폴더를
  지우고, 실패하면 원인을 명시하며 멈춘다.
- 사전 조건(Python 3.13, PyInstaller)을 먼저 확인하고 없으면 설치 명령을 알려주며 중단한다.
  이전 결과물을 먼저 지우므로, 빌드 실패를 성공으로 착각할 수 없다.

### 3.2 자동 실행 스크립트 수정 — `scripts/install_admin_autostart.ps1`

- `dist\smart-alt-tab.exe`가 있으면 **exe를**, 없으면 기존대로 `pythonw.exe run.py`를 작업
  스케줄러 액션으로 등록한다(폴백). 개발 중에는 매번 빌드하지 않으므로 양쪽 다 필요하다.
- 기존 인스턴스 탐지·종료를 `smart-alt-tab.exe`와 `pythonw.exe` **양쪽**으로 확장했다.
  실행 방식을 바꿀 때 이전 방식 인스턴스가 남으면 키보드 훅이 두 개 걸려 중복 동작한다.

### 3.3 배포 페이지 갱신 (gh-pages `index.html`)

- 비활성 "다운로드 준비 중" → **실제 다운로드 버튼**
  (`releases/latest/download/smart-alt-tab.exe`, 릴리스가 갱신돼도 링크는 그대로 유효).
- 사용법을 exe 3단계로 재작성(내려받기 → 두 번 누르기 → Alt 홀드). 소스 실행은 "개발용"으로
  아래로 내렸다.
- 관리자 자동 실행 방법과, 관리자 Cursor/VS Code 사용 시 그 등록이 필요하다는 경고 추가.
- 배지 v0.3.1 → v0.5.0, 업데이트 내역에 v0.4.0~v0.5.0 5줄 추가, 설정(글꼴·크기·5개 언어)
  기능 카드 추가.

### 3.4 문서·버전

- `VERSION`·`version.py`·`pyproject.toml` → 0.5.0, `VERSION_HISTORY` 항목 추가.
- `README.md`: exe 실행을 1순위로, 폐기된 "시작프로그램 폴더" 안내를 작업 스케줄러로 교체,
  exe 직접 빌드 절 추가.
- `CLAUDE.md`: 현재 버전·상태 갱신, M4 제외 확정 명시.
- `docs/prd/`: 마일스톤 표에 M1~M3 완료 버전 기입, M4 제외 사유·재검토 조건 기록.

## 4. 검증 (실행 기준)

| 항목 | 방법 | 결과 |
|---|---|---|
| 빌드 | `scripts\build_exe.ps1` | 성공 — `dist\smart-alt-tab.exe` 10MB, v0.5.0 |
| 실행 | 작업 스케줄러 인스턴스 정지 후 exe 직접 실행 | 성공 — 로그에 `v0.5.0 실행 중 (DPI: per-monitor-v2, 권한: 일반, PID: 30088)`, 콘솔창 없음 |
| 오버레이 | Alt+Tab 주입 후 exe PID 소유 창 열거 | 성공 — `TkTopLevel` 640×164 표시 |
| 창 전환 | Alt 놓은 뒤 포그라운드 확인 | 성공 — `Claude` → `Cursor Agents` 전환 |
| PowerShell 문법 | `Parser::ParseFile` | 두 스크립트 모두 오류 0, UTF-8 BOM 확인 |
| HTML 구조 | `html.parser`로 태그 짝 검사 | 미닫힌 태그 0, 오류 0 |
| 원복 | exe 종료 후 작업 스케줄러 재시작 | 성공 — 관리자 인스턴스(PID 26180) 복구 |

**포커스 원복은 실패했다(코드 문제 아님).** 테스트가 `Cursor Agents`로 전환된 뒤 원래 창으로
되돌리려 했으나 `SetForegroundWindow`가 거부됐다. Cursor가 관리자 권한(High integrity)으로
떠 있고 원복 스크립트는 일반 권한이라, 이미 문서화된 UIPI 제약에 그대로 걸린 것이다.
물리 Alt+Tab(관리자 인스턴스 경유)으로는 정상 복귀된다.
